# 지원사업 서류 만들기

도구: `_src/grant/grant.py` (사용법 `_src/grant/README.md`). 프로젝트 자료는 `_src/grant/projects/<프로젝트>/` 에 두며 **git 에 올리지 않는다** (공개 저장소, `.gitignore` 처리됨). 완성본은 SendUserFile 로 사용자에게 보낸다.

명령은 `_src/grant` 에서 실행: `cd /home/user/donginensis/_src/grant && python3 grant.py ...`
처음이면 `pip install -q -r requirements.txt`. PDF 변환에 LibreOffice Writer·Calc 가 필요하다
(`soffice --version` 이 되는데 변환이 "source file could not be loaded" 로 실패하면 `apt-get install -y --no-install-recommends libreoffice-writer libreoffice-calc`).

## 서식

- **결과물은 워드(DOCX)와 PDF.** 한글(HWP) 파일은 만들지 않는다. 기관 양식이 한글이면 워드로 변환해서 채운다(`work/converted/`).
- **자체 문서는 동인엔시스 문서 서식**(통합경영 매뉴얼 DI-IMS-M-01 과 같은 틀: 로고 표지·빨간 선·문서 정보 표·결재란, 파란 머리행 표, 빨간 밑줄 제목, 맑은 고딕, 꼬리말 "동인엔시스 | 문서명 | 페이지 N / 전체 M"). 틀은 `_src/grant/grantkit/assets/dongin_template.docx`.
- 기관 양식은 기관 배치를 그대로 둔다(회사 서식을 덧씌우지 않음). 문서번호는 사용자가 정해 준 경우에만 넣는다.

## 절대 원칙

1. **지어내지 않는다.** 금액·날짜·번호·실적·업체명은 사업계획서·공고문·협약서·사용자 답변에 있는 값만 쓴다. 없으면 `【확인필요】` 로 남기고 사용자에게 묻는다. `check` 가 이 표시를 오류로 잡는다.
2. **증빙은 실물이어야 한다.** 사진·성적서·데이터는 사용자가 준 실제 파일만 쓴다. 3D 렌더링, AI 생성 이미지, 홈페이지 홍보 이미지를 결과물 증빙으로 넣지 않는다(정산 거절·부정수급 위험). 개념도로 쓸 때는 "개념도"라고 표기한다.
3. **기관 양식이 있으면 양식을 채운다.** 자체 양식으로 대체하지 않는다. 양식이 없을 때만 `build` 로 회사 서식 문서를 만든다.
4. 결과보고서 문장은 계획서의 목표·내용과 실제 결과를 1:1로 맞춘다. 계획 대비 달라진 점은 숨기지 말고 사유와 함께 쓴다.

## 순서

1. **프로젝트 만들기** — `python3 grant.py new <프로젝트>` (예: `2026_성장사다리`). 사용자가 올린 파일을 넣는다:
   사업계획서 → `input/plan/`, 공고문·협약서·정산 안내 → `input/notice/`, 기관 양식 → `input/forms/`, 증빙 → `evidence/`.
2. **읽기** — `python3 grant.py extract <프로젝트>` 후 `work/text/*.md` 를 전부 읽는다. 스캔 PDF 라 글자가 거의 없으면 원본(HWP·DOCX)을 요청한다.
3. **project.yaml 채우기** — 형식은 `_src/grant/example/project.yaml` 을 따른다.
   - `사업`·`기업`·`청구`: 문서에 있는 값만. 계좌·청구일 등 문서에 없는 값은 사용자에게 묻는다.
   - `과제목록`: 계획서의 세부과제·목표·성과지표(목표값·단위). 실적은 사용자 자료로 채운다.
   - `서류목록`: 공고문·정산 안내의 제출서류 전부. `작성` 을 `자동`(양식 채움) · `보고서`(자체 작성: 결과보고서·컨설팅보고서 등) · `자료필요`(증빙 첨부) · `외부발급`(세금계산서·이체확인증·통장사본 등) 중 하나로.
   - `증빙목록`: 각 성과지표·서류에 필요한 실물 자료를 E01, E02… 로. `설명` 에 **무엇을 어떻게 찍을지/받을지** 구체적으로(예: "라인별 설치 위치와 명판이 보이게, 원본 사진 파일로").
4. **요청자료 체크리스트** — `python3 grant.py checklist <프로젝트>` → `output/요청자료_체크리스트.xlsx` 를 보낸다. 파일 이름은 자료 ID 로 시작(`E01_정면.jpg`)하거나 `evidence/E01/` 폴더에 넣으면 된다고 안내한다. 메신저로 받은 사진은 촬영일(EXIF)이 지워지므로 원본 전송을 권한다.
5. **양식 채우기** — `python3 grant.py scan <프로젝트>` 로 `work/forms/<양식>.md`(표 번호·칸 내용·빈칸 후보)와 `fill/<양식>.yaml` 초안을 만든다. 한글 양식은 이때 워드로 변환되므로, 변환본(`work/converted/*.docx`)을 PDF 로 한 번 렌더링해 원본과 배치가 크게 다르지 않은지 확인한다(도형·글상자는 옮겨지지 않음). 초안의 값을 `{{사업.사업명}}` 처럼 project.yaml 변수로 채우고, 쓰지 않는 줄은 지운다. 예시는 `_src/grant/example/fill/`.
   - 라벨 경로: `"라벨 > right"`, `"라벨 > down"`, 여러 단계 `"라벨 > right > right"`. 라벨이 여러 번 나오거나 못 찾으면 `셀: [{표, 행, 열, 값}]` 로 주소 지정.
   - 필터: `|원`(12,000,000원) `|콤마` `|한글금액`(금 일천이백만원정) `|청구금액`(금 일천이백만원정 (₩12,000,000)) `|날짜` `|날짜:%Y년 %m월 %d일`.
   - 문장 속 빈칸은 `바꾸기`(예: `"2026년    월    일"`). 사진을 양식 칸에 넣을 때는 `그림: [{파일, 라벨, 폭mm}]`.
   - `python3 grant.py fill <프로젝트>` 후 실패 항목을 고쳐 다시 실행한다. 결과는 `output/*.docx`(엑셀 양식은 `.xlsx`)와 PDF.
6. **자체 문서** — 결과보고서(기관 양식이 없을 때)·컨설팅보고서 등은 `docs/<문서>.yaml` 을 쓰고 `python3 grant.py build <프로젝트>`. `문서명`(머리말·꼬리말), `표지.결재`(작성·검토·승인 담당; 사용자에게 확인), `강조`(노란 강조 문장)를 쓸 수 있다. 구조 예시 `_src/grant/example/docs/결과보고서.yaml`. 사진은 `사진: [{파일: "evidence/E01_*", 설명}]`, 끝에 증빙 사진 전체를 붙이려면 `사진대지: true`. 사진대지만 따로: `python3 grant.py photos <프로젝트>`.
   - 결과보고서 기본 구성: 1. 사업 개요(목적·기간·사업비) 2. 추진 내용 및 결과(과제별 계획 대비 실적·사진) 3. 성과지표 달성 현황(목표·실적·달성률·증빙 ID) 4. 사업비 집행 현황 5. 기대효과 및 향후 계획 + 별첨 사진대지. 공고문에 작성 요령이 있으면 그 목차를 따른다.
   - 컨설팅보고서: 계획서와 사용자 인터뷰 내용을 바탕으로 현황 진단 → 문제점 → 개선 방안 → 실행 계획 → 기대효과. 근거 없는 수치는 넣지 않는다.
7. **점검** — `python3 grant.py check <프로젝트>`. 오류(빠진 필수 자료, 【확인필요】, 사업비 합계 불일치, 정부지원금 초과 청구, 양식 채우기 실패)를 모두 해결한다. 경고(사업기간 밖 촬영일, 실적 미입력)는 사용자에게 알린다.
8. **전달** — 완성 파일을 SendUserFile 로 보낸다(많으면 `python3 grant.py pack <프로젝트>` 로 zip). `외부발급` 서류는 사용자가 따로 준비해야 한다고 목록으로 알려준다. 보내기 전에 PDF 를 페이지 이미지로 렌더링해 표 넘침·사진 누락이 없는지 한 번 본다.

## 자료를 기다리는 동안

사용자가 일부 자료만 줘도 진행한다: 받은 자료로 문서를 만들고, 빠진 것은 `check` 결과로 정리해 다시 요청한다. 자료가 오면 같은 명령을 다시 실행하면 된다(명세는 그대로 재사용).

## 프로젝트 자료 보관

`projects/` 는 git 에 올라가지 않아 클라우드 세션이 끝나면 사라진다. 작업이 끝나면 사용자에게 완성본을 보내고, 다음에 이어서 하려면 `project.yaml`·`fill/`·`docs/` 를 받아 두거나 비공개 저장소·Google Drive 에 보관하라고 알린다. 공개 저장소에 커밋하지 않는다.
