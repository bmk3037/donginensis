# 통합 기록양식집(DI-IMS-F-01) 원본

`files/iso/DI-IMS-F-01_Rev00.xlsx`와 PDF를 만드는 생성기입니다.

| 파일 | 내용 |
|---|---|
| `forms_data.py` | 양식별 제목·담당·머리 입력란·표 열·미리 적힌 기준·선택 목록·자동 계산 수식 |
| `build_forms.py` | 공통 배치(머리 입력란, 표, 결재란, 인쇄 설정)와 엑셀 저장 |
| `logo.png` | 양식 왼쪽 위 로고 |

## 고치는 방법

1. `forms_data.py`에서 문구·행·열을 고칩니다. 열 너비는 비율만 맞으면 되고 용지 폭에 맞게 자동으로 늘어납니다.
2. 엑셀 생성: `pip install openpyxl pillow` 후 `python3 _src/iso/build_forms.py`
3. PDF 생성: `soffice --headless --convert-to pdf --outdir files/iso files/iso/DI-IMS-F-01_Rev00.xlsx`
   - LibreOffice Calc가 필요합니다. 맑은 고딕이 없는 환경에서는 `_src/profile/fonts`의 Pretendard로 대체하면 한글이 깨지지 않습니다(fontconfig 별칭).
   - 엑셀과 같은 열 너비로 인쇄되도록 Carlito 글꼴(Calibri 호환)이 있어야 합니다.
4. 양식을 추가·삭제하면 매뉴얼 부록 C, `forms_data.py`의 `FORMS` 목록, `resources.html`의 쪽수·종수를 함께 고칩니다.

## ISO 기록 묶음 생성기 (프로젝트별 양식 자동 채우기)

`tool/` 폴더는 브라우저에서 쓰는 생성기입니다. 프로젝트 정보·BOM·I/O 리스트·시험 기준표를 넣으면
프로젝트 폴더(01_수주고객 ~ 08_NCR_AS)와 양식 엑셀(PF-00, QF-02~16, SF-02·03)을 채워 zip으로 저장합니다.
실측값·판정·서명 칸은 비워 둡니다.

| 파일 | 내용 |
|---|---|
| `tool/engine.js` | 양식 배치 엔진(`build_forms.py`의 자바스크립트판) |
| `tool/project.js` | BOM·I/O·기준표 읽기, 만들 문서 목록, zip 생성 |
| `tool/samples.js` | 예시 데이터(가상의 인버터 제어반 2면) |
| `tool/app.js`, `tool/app.css`, `tool/page.html` | 화면(탭 전환, 다른 탭과 공유하는 `window.IsoApp`) |
| `tool/labels.js` | 02 명판·라벨: 판넬 LOT 명판(실제 크기 SVG, QR), A4 라벨지 인쇄, 라벨 프린터용 CSV |
| `tool/fat.js` | 03 FAT 시험 입력: 항목·I/O 점별 판정(시각 자동 기록) → QF-06·06-1 엑셀, 고객 제출용 성적서 |
| `tool/dash.js` | 04 기록 현황판: 공용 저장소 폴더의 00_기록현황·QF-04·00_프로젝트정보를 모아 진행 단계 표시, 도면_승인본·07_PLC/릴리스의 최신 Rev·버전과 기록(도면 Rev·PLC Ver·FAT 시험 버전) 비교 |
| `tool/annual.js` | 05 회사 연간 기록: 시행일부터 15개월 회사 단위 기록 기한(법정 안전보건·내부심사·경영검토·교정·교육 등), 회사기록 폴더의 '양식번호_연월' 파일로 완료 확인, 계획표 엑셀·캘린더(.ics), 할 일별 '양식 받기'(회사 양식 21종을 담당자·기간·결재란 채우고 작성 예시 넣어 규칙 파일명으로 저장) |
| `build_tool.py` | 위 파일과 `forms_data.py`의 양식 정의를 묶어 한 파일로 만든다 |

- 다시 만들기: `python3 _src/iso/build_tool.py` → `tool/dist/ISO-기록생성기.html`
- 위 빌드 후 프로젝트 저장·복원, 판넬 수량, 양식 대응·공통기록 참조 검증: `node _src/iso/tool/check_project.cjs`
- `00_기록현황` 엑셀에는 프로젝트 현황과 `공통기록참조` 두 시트가 있습니다. 공급자·교정·자격·백업·안전·환경·경영 기록은 회사 원본의 관리번호·Rev·경로를 연결하며 프로젝트마다 중복 생성하지 않습니다. 확인 상태 입력은 실제 승인 원본을 대신하지 않습니다.
- 프로젝트 총수량을 판넬별 배분한 BOM은 배분 전 원본 총수량 BOM을 별도로 올려 대조합니다. 품명·모델·메이커·단위를 같게 쓰고, 수량은 숫자와 단위로 분리합니다. 누락·초과·원본에 없는 부품을 차단하며 빈 수량을 1개로 추정하지 않습니다. 원본 BOM의 승인 Rev와 실제 증빙은 별도 확인합니다.
- 쓰는 법: 이 HTML 파일을 회사 공용 저장소에 두고 크롬·엣지로 엽니다(엑셀 라이브러리를 인터넷에서 불러오므로 인터넷 연결 필요).
- 회사 BOM·I/O 파일은 브라우저 안에서만 처리되고 밖으로 보내지 않습니다. 실제 프로젝트 파일이나 생성 결과는 이 저장소에 올리지 않습니다.
- 묶음에는 `00_프로젝트정보_*.json`(입력 내용)이 들어갑니다. 공용 저장소에 풀어 두면 다른 담당자가 현황판에서 그 프로젝트를 열어 이어 씁니다.
- 직접 적는 칸의 작성 예시(`project.js`의 `EXAMPLES`)는 판넬 1면 기준으로 1번 판넬 문서와 공통 문서 표 첫 행에 회색 '예)' 글로 들어갑니다. 현황판은 '예)' 값을 실제 기록으로 세지 않습니다.
- 인쇄(명판·라벨·성적서)는 화면 안 숨은 틀로 인쇄 창을 열고, 열 수 없는 환경(아티팩트 등)에서는 인쇄용 HTML 파일을 받아 크롬에서 인쇄합니다.
- `forms_data.py`의 양식을 고치면 `build_forms.py`와 `build_tool.py`를 둘 다 다시 실행합니다.

## 배치 규칙

- 1장 양식(`mode='single'`): A4 한 장에 맞춰 인쇄합니다.
- 대장 양식(`mode='register'`): 빈 행을 마지막 쪽 끝까지 채우고, 행이 늘면 여러 장으로 나뉘며 표 머리글이 반복됩니다.
- 회색 칸은 미리 적힌 기준, 흰 칸은 입력 칸입니다. 판정 칸은 선택 목록이며 불합격·미흡 등은 붉게 표시됩니다.
- 자동 계산: QF-10 평균·등급, QF-12 종합, SF-01 위험도·판정, SF-07 집행률·합계, SF-09 총점·판정, EF-01 점수·중요 판정, QF-11 차기일 경과 표시.
- 이 폴더(`_src`)는 홈페이지에 공개되지 않습니다.

- 현황판은 NCR·AS까지 포함하여 확인일·확인자·선택 폴더 내 승인 증거 파일을 대조한 프로젝트 증빙 연결률을 표시합니다. 해당없음은 확인일·확인자·사유가 필요합니다. 증거·대체 기록은 프로젝트 폴더 기준 상대경로 또는 선택 폴더 내 경로로 연결합니다. 실제 내용·서명·권한과 공통 경영 기록의 적합 여부는 별도 확인합니다. FAT 불합격·보류·판정 미확인을 합격·출하 확인 대상으로 집계하지 않습니다. 검증: `node _src/iso/tool/check_dashboard.cjs`.
- FAT는 시험을 시작한 판넬 LOT·도면/BOM/I/O/PLC/시험 기준과 실제 시험 행을 저장합니다. 기준 또는 BOM·I/O 내용이 달라지면 이전 결과의 성적서 출력과 합격 이어쓰기를 막고, 이전 기록 JSON 보관 후 빈 시험 기록을 시작합니다. 구형 기록은 기준 정보가 없어 재시험 대상으로 표시하며 원본은 보관할 수 있습니다. JSON 교체와 새 시험 시작 전에 기존 기록을 다운로드하고 이 기기에도 별도 보관합니다. 다운로드 파일의 보관 여부는 확인하여 공용폴더/NAS에 옮겨야 하며, 브라우저 저장소는 회사 백업을 대신하지 않습니다. 다른 수주번호·판넬 또는 잘못된 형식의 JSON은 불러오지 않습니다. 검증: `node _src/iso/tool/check_fat.cjs`.
