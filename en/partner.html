Data

Different machines,
one data structure

Data is delivered as equipment → sensor → value → status, so adding machines does not mean rewriting your integration.

  • 01Grouped by machinesite_id and equipment_id tell you which site and which machine the data comes from.
  • 02Every sensor, one formatTemperature, current or vibration, each sensor reports value, unit and status the same way.
  • 03Status from thresholdsEach sensor is judged against its own warning and alarm thresholds; if any sensor is in warning, the machine is too.
// Example payload (for illustration) { "site_id": "PLANT-01", "equipment_id": "PUMP-01", "timestamp": "2026-10-07T09:30:00+09:00", "status": "warning", "sensors": [ { "id": "bearing_temp", "value": 48.2, "unit": "°C", "status": "normal" }, { "id": "motor_current", "value": 31.6, "unit": "A", "status": "normal" }, { "id": "vibration", "value": 4.8, "unit": "mm/s", "status": "warning" } ] }

Actual fields and update intervals are agreed in a technical meeting.

FAQ

Frequently asked questions

Which PLCs do you support?

We are not tied to a single manufacturer. Any PLC that supports MQTT can be built into the Intelligent Control Panel, and for PLCs already installed at customer sites we review the model and communication method and propose an integration approach project by project.

How is the data delivered?

Through REST API and WebSocket. Data points and update intervals are agreed in the technical meeting. Get the overview and sample data →

Can we test before committing?

Yes. We can verify the integration with your platform using demo equipment and test data first.

How are data ownership and contracts handled?

Roles and data use between the customer, your company and DONG-IN ENSIS are defined in each project contract.
